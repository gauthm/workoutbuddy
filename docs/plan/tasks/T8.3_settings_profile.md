   TOUTES les infos personnelles stockées que le coach injecte dans ses

3. **Reset complet** avec double confirmation : remise à zéro de tous les
   champs + relance de l'onboarding.
4. **Backend** : rendre effaçables les champs aujourd'hui non-nullables
   (`age`, `sex`, `fitness_level`, `primary_goal`, `sessions_per_week`,
   `session_duration_min`) + endpoint `DELETE /user-profile`.
5. **Gating du coach dans le prompt système** (`systemPromptBuilder.js`) :
   - profil incomplet → **INTERDICTION de créer un programme** ; le coach

### 1. Rendre les champs effaçables (mise à jour du `PROFILE_SCHEMA`)

Problème actuel : `validateField` refuse `null` sur les types `number` et
`enum`. Impossible donc de vider `age` ou `sex` individuellement.

Remplacer les entrées concernées :

```javascript

  display_name:              { type: 'string_nullable' },
  age:                       { type: 'number_nullable', min: 10, max: 100 },   // ← était number
  sex:                       { type: 'enum_nullable', enum: ['male','female','other','prefer_not_to_say'] }, // ← nouveau type
  weight_kg:                 { type: 'number', min: 20, max: 500 },            // inchangé (toujours requis si fourni non-null? non → voir note)
  height_cm:                 { type: 'number', min: 50, max: 280 },
  fitness_level:             { type: 'enum_nullable', enum: ['beginner','intermediate','advanced','athlete'] },
  primary_goal:              { type: 'enum_nullable', enum: ['strength','hypertrophy','endurance','weight_loss','general_fitness','sport_performance'] },
  secondary_goals:           { type: 'json_array' },
  target_weight_kg:          { type: 'number_nullable', min: 20, max: 500 },
  sport_practiced:           { type: 'string_nullable' },
  sessions_per_week:         { type: 'number_nullable', min: 1, max: 7 },      // ← était number
  session_duration_min:      { type: 'number_nullable', min: 15, max: 240 },   // ← était number
  prefers_exercise_variation:{ type: 'boolean_int' },
  injury_notes:              { type: 'string_nullable' },
  medical_notes:             { type: 'string_nullable' },

  onboarding_step:           { type: 'string' },

```

**Note importante `weight_kg` / `height_cm`** : passer aussi ces deux en
`number_nullable` — un utilisateur qui ne veut plus partager son poids
doit pouvoir le vider. Le prompt du coach gère déjà l'absence de ces
champs (`buildProfileSection` filtre les null).

Dans `validateField`, ajouter la gestion `enum_nullable` — modifier le
bloc `switch` existant :

```javascript
    case 'enum':
      if (!schema.enum.includes(value)) return { valid: false, error: `${key} : valeurs valides = ${schema.enum.join(', ')}.` }
      break
    case 'enum_nullable':                     // ← AJOUTER
      if (value !== null && !schema.enum.includes(value))
        return { valid: false, error: `${key} : valeurs valides = ${schema.enum.join(', ')}, null.` }
      break
```

Et dans la branche null en tête de fonction, ajouter `enum_nullable` aux
types acceptant null :

```javascript
  if (value === null || value === undefined) {
    if (['string_nullable','number_nullable','enum_nullable'].includes(schema.type)) return { valid: true }
    if (schema.type !== 'json_array') return { valid: false, error: `${key} ne peut pas être null.` }
  }
```

Les colonnes SQL de `003_user_profile.sql` sont déjà nullables → aucune
migration nécessaire.
